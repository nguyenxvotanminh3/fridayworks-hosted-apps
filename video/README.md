# Friday Works video editor

A browser video editor that works on phones as well as computers. It is a modified copy of the classic web app of [OpenCut](https://github.com/OpenCut-app/OpenCut) (`apps/web` at commit `cf5e79e`), released under the MIT License (see `LICENSE`). Friday Works embeds it in the Tools section of [fridayweworks.com](https://fridayweworks.com/vi/tools). OpenCut's name and logos are not used for this build.

## What differs from upstream

- **Static.** The app is a static export (`output: "export"`) that can be served from any file host under a sub-path (`NEXT_PUBLIC_BASE_PATH`). Accounts, the database, rate limiting, analytics, bot protection and the sound search that needed OpenCut's servers are removed. Only the AI assistant talks to a server, fridayweworks.com's API.
- **Nothing of the visitor's kept on the device.** Projects and imported media live in memory for the visit (`src/services/storage/memory-adapter.ts`); nothing is written to IndexedDB or OPFS. Exporting downloads the video. Automatic captions download a public speech model from huggingface.co, which the browser keeps in its cache (Cache Storage) so the next run does not fetch it again. localStorage keeps small interface settings (panel sizes, shortcuts, timeline and preview toggles) and the ids of recently used stickers. Besides this site, the editor contacts Google Fonts (when fonts are previewed or used) and cdn.brandfetch.io (platform logos in the upstream safe-area guide menu). The AI assistant sends what is typed in it and a text description of the project (sizes, times, file names, the text on the video; never the media) to fridayweworks.com, which asks DeepSeek and stores the conversation.
- **Phone layout.** Narrow screens, and touch screens turned sideways, get a CapCut-style layout (`src/components/editor/mobile/`): the preview on top, the timeline below and the tools along the bottom edge. Asset tabs and clip properties open in a sheet over the timeline. The upstream "desktop only" screen is gone.
- **Touch input.** The timeline, trim handles, playhead, preview handles and colour picker use pointer events. A swipe on an unselected clip scrolls the timeline, a tap selects it, and a selected clip can be dragged. Two fingers zoom the timeline. On touch screens a tap on a media, text or sticker card adds it.
- **Quick import.** "Add" puts picked photos and videos straight onto the timeline one after another, and the frame takes the first clip's size, so vertical phone footage fills the frame.
- **Vietnamese or English.** The interface follows `?lang=vi` / `?lang=en` (else the browser language). Labels that upstream registries define in English (parameters, masks, shapes, effects) are translated by their English text (`src/i18n/labels.ts`); language and country names come from the browser (`Intl.DisplayNames`), and the flag search also finds Vietnamese names, with or without tone marks. Vietnamese terms follow CapCut, Clipchamp, Canva and Google Photos.
- **CapCut-style timeline on phones.** The playhead stays in the middle and the timeline moves under it (`src/timeline/center-playhead.ts`): a swipe scrubs, playback scrolls the timeline, a touch pauses, and pinching keeps the time under the playhead. Holding a clip still for a moment picks it up for dragging. The first clip opens at about 100 px per second, and the outermost 16 px ignore touches.
- **Exports survive a stray tap.** Closing the export panel no longer cancels a running export (upstream issue #848); the Export button shows the percentage, and cancelling asks for a confirmation.
- **Phone tool row.** Six buttons that always fit the screen (Add, Text, Effects, Ratio, Captions, More), a ratio menu (9:16, 16:9, 1:1, 4:3), and toasts placed under the top bar, clear of Export and of the tool menus; a toast still showing closes when the export panel opens.
- **Lighter exports.** The file is written in chunks and joined into a Blob at the end (`src/export/chunked-file.ts`) instead of one growing buffer plus a copy. Footage above 1080p exports at 1080p on phones unless the original size is picked; videos over 3 minutes get a memory warning, and an out-of-memory failure says so. Browsers without an audio encoder (Safari before iOS 26) export silent video with a notice. One tap exports for TikTok/Reels (9:16) or YouTube (16:9). New projects are named by date and time.
- **Captions on phones.** whisper-base (about 150 MB the first time) instead of whisper-small (about 300 MB); the panel shows both with their download size, and Vietnamese pages preselect Vietnamese.
- **Outline, shadow and caption looks.** Text has an outline (`stroke.*`) and a drop shadow (`shadow.*`), sized in percent of the font size; the shadow is mapped through the canvas transform, so it follows scale and rotation. The Captions tab offers six looks of Friday Works' own (`src/subtitles/caption-styles.ts`) for generated captions and imported SRT files; ASS files keep their own styles.
- **Vietnamese captions cut by length.** Vietnamese writes one syllable per word, so three words per caption is too short. Vietnamese transcripts are cut after punctuation and into even parts of about two lines (`buildCaptionChunksByLength`), wrapped lines are balanced, and caption text is stored in composed Unicode (NFC).
- **Fonts that draw Vietnamese.** The text Font field opens the font list, which upstream used only for text masks, and Vietnamese pages open it on a Vietnamese tab: the 519 atlas families that include Google Fonts' Vietnamese subset (`src/fonts/vietnamese-fonts.ts`, from the Fontsource catalogue) and the system fonts. A picked font now loads its Vietnamese files before it is applied: upstream loaded only the Latin file, so letters with tone marks were drawn in a fallback font.
- **Commands for AI agents.** `src/ai/` gives AI agents a text command interface to the whole editor: 46 commands (import media, text, captions, stickers, effects, masks, keyframes, transitions, sound analysis and noise reduction, speed, trims, snapshots, export) that call the editor's own commands, so undo and autosave work. Opening the page with `?ai=1` shows the console beside the editor; `window.fridayworksAI.run("…")` runs the same commands from JavaScript; browsers with WebMCP get one tool per command. Errors come with hints, `snapshot` returns a PNG of a frame, and text that runs outside the frame is reported. The command list in `src/ai/spec.ts` also generates `help`, the WebMCP schemas and `public/llms.txt` (`node --experimental-strip-types scripts/ai-docs.mjs`).
- **AI assistant.** An "AI assistant" tab on computers, and a button at the top left on phones, chat with DeepSeek through fridayweworks.com's API (`src/ai/assistant/`). A request goes with the project state; DeepSeek answers with calls of the editor's commands (all but help, snapshot, media import, export, play and pause: `src/ai/agent-tools.ts`), which the editor runs with the console's engine and reports back until DeepSeek answers in words. The site stores the conversations to evaluate and train the assistant, which the panel says in one line. `node --experimental-strip-types scripts/ai-docs.mjs --assistant-tools <file>` writes the tool list the site's API offers.
- **Transitions.** `src/transitions/` adds dissolve, fade (through the background colour), zoom, blur and four slides at a cut between two clips that touch on the main track. A transition is stored on the second clip and centred on the cut: the renderer shows both clips for its length and blends them, and the clips keep their places, so the video keeps its length; past a clip's source its first or last frame repeats. Two parts of one file read from two decoders. Sound still cuts at the cut. Only the AI commands (`transition add`, `transition remove`) set transitions so far.
- **Noise reduction and sound analysis.** `src/audio-cleanup/` runs RNNoise (BSD-3-Clause, built to WebAssembly by `@shiguredo/rnnoise-wasm`, Apache-2.0; a 4.8 MB module loaded on first use). `audio denoise` cleans a span of a clip's sound in preview and export and keeps voices: noise without a voice is removed almost completely, noise under a voice is lowered. `audio analyze` reports where someone speaks, where speech has noise under it, where there is other sound and where it is quiet. The cleaning is kept in the source's seconds, so it follows the sound when the clip moves. Licences: `THIRD_PARTY_LICENSES.md`.
- **Cooler when idle, lighter preview.** The preview asked for a frame 60 times a second for as long as the page was open; it now draws when the playhead, the scene or the preview's size changes, and every frame only while playing. It draws at the size it is shown (with the screen's pixel density, at most 2×, and the preview zoom) instead of the project's 1080×1920 or 4K, and decodes video frames no larger; exports and snapshots still draw at full size. The playback sound engine (`AudioContext`) sleeps when playback stops, and the ones made only to decode or mix (exports, captions, library sounds) are closed afterwards; upstream left them running until the page closed. The effects sample picture loads when an effect preview is first shown. While playing, the clock reports only new video frames, and the preview, the playhead and the timecodes change together in that one browser frame (upstream composed two or three per video frame); the playhead moves with a transform, the phone timeline no longer re-renders on every scroll step, and decoders shrink frames at most by half, which takes one draw per frame instead of two or three.
- **Works without a graphics card.** Upstream composites every frame with WebGPU or WebGL (`opencut-wasm`); without either (virtual machines, blocked drivers) the page stopped with "GPU context not initialized". `src/services/renderer/compositor/canvas-compositor.ts` draws the same frame descriptor with Canvas 2D on the CPU, following the wasm shaders: W3C blend modes, opacity, rotation and flips, Gaussian blur with clamped edges and per-axis strength, masks with soft edges, effect layers. The editor starts the GPU only for a hardware WebGPU adapter or a WebGL2 context that passes `failIfMajorPerformanceCaveat`, because a software-emulated GPU (SwiftShader) is many times slower than Canvas 2D; if the wasm compositor fails later, drawing moves to the CPU for the rest of the visit.
- **Save or share after export.** On phones a finished export waits in the panel: "Save or share" opens the phone's share sheet (Save Video to Photos, Zalo, TikTok) through the Web Share API, and "Download" downloads it. A page that embeds the editor must allow `web-share` on the iframe.
- **Leaving with unexported work.** The editor tells the page that embeds it whether the video has changes that were never exported (`src/project/unexported-work.ts`), so the page can ask before leaving; iPhone Safari never shows a "leave site?" prompt.
- **Fixes upstream could not take.** The video cache answered an overtaken request with its current frame, which a just-opened decoder does not have yet, so a frame could come back empty; it now decodes that request instead. After an export the preview kept the last exported frame, because the exporter draws through the compositor whose canvas is the preview; the preview now redraws the playhead's frame when an export ends. Streaming waveform decode from [hp-8/opencut-classic](https://github.com/hp-8/opencut-classic/commit/d5c906dac6ed59c798e1335808974267550d44db) (MIT, upstream #594, #656). A preview stuck on an old frame after a far seek: video frames come from a pool of three canvases and the compositor kept the texture of a reused canvas (`sourceRevision`), a likely cause of #584. An effect layer broke the GPU compositor ("missing field `effect_pass_groups`"): serde's `rename_all` on the Rust enum renames the variant but not its fields, so the scene-effect item now sends the snake_case name.
- **Smaller fixes.** New text is sized to the width of portrait frames, font previews load only when the font picker opens, and blob downloads are released after a delay so iOS Safari keeps them.

## Build

```bash
npm ci
NEXT_PUBLIC_BASE_PATH=/fridayworks-hosted-apps/video npm run build
```

The site is written to `out/`. Leave `NEXT_PUBLIC_BASE_PATH` empty to serve it from the root of a host.
